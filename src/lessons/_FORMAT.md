# 课程文件格式（写课之前先读这一份）

一节课 = 一个文件 `src/lessons/LessonNN.js`，**只导出数据，不写 JSX**。
长什么样由 `src/learn/` 里的组件负责，你只负责内容。

## 骨架

```js
export default {
  meta: {
    id: 4,                                   // 必须和文件名 Lesson04.js 对得上
    title: 'State 与 useState',              // 课表里显示的标题
    stage: '阶段一 · 组件的思维',             // 只能用下面三个之一，一字不差
    goal: '让页面动起来：数字能被点击改变',    // 课表副标题，20 字以内
    minutes: 25,                             // 预计学完的分钟数
  },
  blocks: [
    /* 见下 */
  ],
}
```

三个阶段的名字必须一字不差：

- `阶段一 · 组件的思维`
- `阶段二 · 数据和状态往哪放`
- `阶段三 · 做一个真东西`

## block 类型

| type     | 字段                        | 用途                                |
| -------- | --------------------------- | ----------------------------------- |
| `text`   | `md`                        | 普通正文                            |
| `note`   | `md`, `title?`              | 蓝底：为什么要学这个、核心结论      |
| `warn`   | `md`, `title?`              | 黄底：最容易踩的坑                  |
| `tip`    | `md`, `title?`              | 绿底：正确做法、口诀                |
| `bonus`  | `md`, `title?`              | 灰底：加分题、延伸                  |
| `code`   | `code`, `title?`            | 只读代码，不给改                    |
| `demo`   | `code`, `task?`, `height?`   | 练习场：可编辑 + 真运行             |
| `quiz`   | `question`, `options[]`     | 小测，点一下立刻有反馈              |
| `task`   | `items[]`, `title?`         | 动手任务（可打勾）                  |
| `check`  | `items[]`                   | 自查清单（可打勾）                  |

- `md` 和 `task`（练习场里的引导文字）推荐写成**「一行一个字符串」的数组**：

  ```js
  md: [
    '这是普通的一段话，行内的 `代码` 和 **加粗** 都支持。',
    '',
    '空字符串表示一个空行。',
    '```',
    'code: 三个反引号围起来可以夹一小段代码',
    '```',
  ]
  ```

  为什么用数组：字符串里要用反引号表示行内代码，用模板字符串（`` ` ``）会撞车。用数组 + 单引号就完全不用转义。
  短的单行文案也可以直接写字符串，同样用单引号。

  **注意**：单引号字符串里不要再出现英文单引号 `'`（会截断字符串）。要提到 JS 里的字符串时用双引号，例如 `"react"`；中文里用「」引号。
- 不要用标题、表格、图片、链接、HTML。
- 打勾清单的 `items` 是字符串数组，每项一到两句话。
- `demo` 的 `height` 是预览窗口高度，默认 240；内容高（多张卡片）可以给 320~360。
- `quiz` 的 `options` 形如 `[{ text, correct?, why }]`：**有且只有一个** `correct: true`。`why` 是选中后显示的讲解，要解释「为什么」，不要只说「不对」。

## 一节好课的形状（顺序照抄）

1. `note` 「为什么要学这个」——用上一课留下的痛点开场，2~4 句。
2. `note` 知识点 1 —— 把最核心的一句话讲透。
3. `warn` 或 `note` 知识点 2 —— 机制层面「背后发生了什么」。
4. `tip` 口诀 / 正确姿势。
5. `demo` 一个「反例」：先让人看到错误写法会发生什么，任务里让他点一点、猜一猜。
6. `demo` 一个「正解」：开头就写对，任务里留 1~2 个 TODO 让他补齐。（正例反例顺序可以按主题调换）
7. `quiz` 1~2 个。
8. `code` 一小段只读代码（对照写法 / 真实项目里的样子）。
9. `task` 动手任务 3~4 条。
10. `check` 自查清单 4 条 —— 每条都必须是「能在屏幕上验证」的，不要写「理解了 xxx」。
11. `bonus` 加分题 1~2 条。

一个文件里：`demo` 1~3 个、`quiz` 1~2 个、`task` 1 个、`check` 1 个，块总数 12~20。
写课的口吻跟 `Lesson04.js` 保持一致：先说人话，再给术语；面向成年自学的人，别哄小孩。

## demo 代码的硬规矩（自检脚本会真编译、真渲染一遍）

- 必须**自给自足**：不 import 本地文件，不联网，不用 `document` / `window`（`localStorage` 要用 `try/catch` 包起来）。
- 组件必须叫 `App`，或者最后 `export default` 出来。`import { useState } from 'react'` 照写，运行时会自动处理；没写 import 也会自动把 hook 补进作用域。
- 不要写死循环、不要故意让页面卡住；反例要「效果不对但不崩」。
- **反例 demo 必须是「能跑起来、但结果不对」的写法**（比如改了普通变量页面不刷新、直接把数组 push 进去、`length && ...` 在空数组时渲染出一个 0）。
  **语法错误的反例不能做成 demo** —— 它编译不过，自检脚本会直接判失败。语法错误的例子放进 `code` 只读块或任务文字里。
- 一进来就能看到东西，不要白屏或只显示「加载中」。
- **每行不超过 58 个字符**（手机上不折行）；整个 demo 不超过 48 行。
- 预览窗口里已内置这些 class（见 `src/styles/base.css`，可以直接用）：
  `card` `row` `stack` `tag` `chip` `btn`(`primary`) `field` `list` / `list-item` `muted` `small` `big` `good` `bad` `hint` `empty` `checkbox`
- 文案像真实小应用里的中文，不要「foo / bar / 测试1」。

## 写完自己验一遍

```bash
node scripts/check-lessons.mjs 5
```

结构问题、quiz 答案个数、示例代码编译或渲染失败都会报出来。必须 **0 问题**。
